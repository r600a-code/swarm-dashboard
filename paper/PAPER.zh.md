## 摘要

单一的大语言模型，无论多强，都是一个被迫对一切都"还行"的通才，因而对任何特定领域都不是卓越的。当智能体的负载异质时——一个 reflexion 陷阱、一段代码、一句翻译、一个常识——没有一个模型对所有都合适。我们提出**Agent 的多专家模式**：一种智能体架构，其中*协调器*分解一批任务，*纯路由器*把每个任务指派给与任务难度/模态匹配的*专用专家模型*，*并行下放器*把每个指派实现为一个绑定到该模型的隔离子智能体——同时*反馈回路*把真实结果折回路由，*计量器*核算精确成本。该框架与宿主无关：任何暴露（1）可插拔模型注册表、（2）子智能体委派缝、（3）流级用量事件的系统都能实现它。我们给出形式模型，证明在温和假设下按难度匹配的路由帕累托优于单模型下放，并给出在 DeepSeek Harness 上的首个验证实现（`dsh-swarm-router`）：在真实 cfgpu 驱动的基准上，五个异质任务路由到四个不同模型、全部答对，并逐任务归属 token。我们论证该模式在理论上可实例化任何可表达为模型路由的专家——因此趋近"任何想法，皆有其专家"。

## 1. 引言

主流智能体架构把一个模型钉在一个智能体上。操作上简单，但在负载非均匀时经济上是错的。代价有二：**过度供给**（旗舰推理模型回答"17×23 是多少"）与**欠供给**（便宜快模型栽进 bat-and-ball 陷阱）。修法看似显然——不同任务用不同模型——但实践中罕见，原因有三：

1. **选模型是部署选择，非按任务决策。** 模型路由在启动时配一次，智能体无法在负载中途重路由。
2. **用一次模型调用来选择，在任何真正工作开始前就先花一个往返**，侵蚀了促发路由的延迟节省。
3. **能纠正糟糕静态排名的反馈从不被收集。** 看着强但实际失败的模型永不被降权。

多专家模式通过分离单模型架构所混淆的四个关注点来解决这三点：决定哪个专家合适、下放给它、从结果学习、核算成本。

**贡献。**
1. 多专家路由的形式模型——任务、专家、指派、下放、结果——及最优性定义（§2）。
2. 在温和成本/能力假设下按难度匹配路由帕累托优于单模型下放的证明（§3）。
3. 四组件架构——路由器、下放器、反馈、计量器——可在满足三个缝要求的任何宿主上实现（§4）。
4. DeepSeek Harness 上的首个验证实现（`dsh-swarm-router`），含跨四个 cfgpu 模型的真实基准（§5）。
5. 论证该模式原则上可实例化任何可表达为模型路由的专家，使其成为"任何想法 → 其专家"的基底（§6）。

## 2. 形式模型

### 2.1 原语

令 **T** 为任务，元组 `(k, p, m)`：
- `k ∈ K` 为*种类*——离散能力类（如 `{reasoning, coding, longcontext, fast, general, translation, vision, ...}`）。K 是开放的：注册新种类无需改码。
- `p` 为*提示*——交付给专家的自然语言指令。
- `m*` 为可选*输出上界*（最大 token）。

令 **E** 为专家，元组 `(r, id, caps, ranks)`：
- `r` 为*路由*——provider 端点（如 `cfgpu-swarm`、`openrouter`）。
- `id` 为该路由内的*模型 id*。
- `caps ⊆ {reasoning, coding, longContext, fast, vision, ...}` 为布尔*能力标签*。
- `ranks: {strength, speed, cost, contextWindow, ...} → ℕ` 为标量*质量/效率排名*，`cost` 越高越*便宜*。

令 **C** = {E₁,…,Eₙ} 为可用专家*目录*。

### 2.2 路由器

**路由器**是函数 `ρ: T × C → E ∪ {⊥}`，把任务指派给专家（或 ⊥ 表示无合格者）。它复合三阶段：

1. **能力门** `g: T × E → {0,1}`——`g(T,E)=1` 当且仅当 `E.caps ⊇ require(k)`，其中 `require: K → 2^Caps` 把种类映到所需标签。缺标签者硬过滤。
2. **评分** `s: T × E → ℝ`——按难度匹配的线性组合 `s(T,E) = Σ_c w_k(c)·E.ranks(c) − penalties(T,E)`，`w_k` 为种类专属权重，penalties 编码失配（如快档专家做质量活）。
3. **选定**——存活者取 argmax，确定性平局。

### 2.3 下放、结果、反馈

**下放器** `δ: 指派 → 结果` 把 `ρ` 的指派实现为绑定到 `E` 的隔离执行（子智能体或直接调用），返回 `result = {output, stopReason, usage}`。

**结果** `o = (T, E, correct, quality)` 记录专家答得对不对、有多好。

**反馈函数** `φ: o → Δrank` 把结果折成加成，叠加在 `s` 之上：`s'(T,E) = s(T,E) + β(rankings, E, k)`。目录的静态排名是先验，加成是后验。

**计量器** `μ: result → usageᵀ` 提取 token 核算，按（专家, 任务）归属。

### 2.4 最优性

**定义（按难度匹配）。** 指派 `(T,E)` 按难度匹配当且仅当 `E` 在 `quality(E,T) ≥ τ(k)` 约束下最小化 `cost(E)·1[capable(E,T)]`——即过任务种类质量门槛的最便宜专家。

**定义（帕累托优于）。** 批 `B` 上的路由 `R` 帕累托优于 `R'` 当且仅当 ∀T∈B：`cost_R(T) ≤ cost_R'(T) ∧ quality_R(T) ≥ quality_R'(T)`，且 ∃T：严格。

## 3. 定理：按难度匹配路由帕累托优于单模型下放

**定理 1.** *令 `B` 为至少含两种不同种类的任务批。令 `E*` 为任一单专家。令 `R_M` 为按难度匹配路由，`R_1` 为在 `E*` 上的单模型路由。假设：*

*(A1) 能力单调性：*存在专家 `E_fast, E_strong`，`cost(E_fast) > cost(E_strong)`（快更便宜），`quality(E_fast, fast-kind) ≥ τ(fast)` 但 `quality(E_strong, reasoning-kind) > quality(E_fast, reasoning-kind)`（强专家对难题更强）。

*(A2) 非退化：*`B` 至少含一个 `E*` 过供给（有更便宜且胜任者）或欠供给（`E*` 不过质量门槛）的任务。

*则 `R_M` 帕累托优于 `R_1`。*

**证明.** 按 (A2) 分情形：

- **过供给任务** `T_o`：`E*` 过 `τ` 但 `∃ E_c`，`cost(E_c) > cost(E*)`（更便宜）且 `capable(E_c, T_o)=1`。则 `cost_R_M(T_o) < cost_R_1(T_o)` 且 `quality_R_M(T_o) ≥ τ = quality_R_1(T_o)`（两者都过门槛）→ 严格成本改善，质量持平。
- **欠供给任务** `T_u`：`quality(E*, T_u) < τ`。若 `∃ E_s`，`quality(E_s, T_u) ≥ τ`，则 `quality_R_M(T_u) > quality_R_1(T_u)`，且按难度匹配 `cost_R_M(T_u)` 为最便宜之 `E_s` ≤（不存在的）`E*` 过门槛之成本 → 严格质量改善，成本不劣。

由 (A2) 至少一情形严格成立；其余任务在 `R_M` 下不劣（本可用 `E*`）。 ∎

**注.** 假设温和：(A1) 对任何含快档与强档的目录成立（cfgpu 真如此：Flash vs GLM-5.2）。定理说基准所证：算术走 Flash、陷阱走 GLM-5.2，比全用任一者都严格更便宜且更正确。

## 4. 架构

四组件，宿主无关给定三个缝：

```
        ┌─────────────┐   任务    ┌──────────┐  指派   ┌──────────────┐
批次 → │  协调器      │ ────────→ │  路由器  │ ───────→ │  下放器      │
        │ (分解)      │           │ ρ: 纯    │         │ δ: 并行      │
        └─────────────┘           └────┬─────┘         └──────┬───────┘
                                       │ 反馈加成            │ 结果
                                       ▼                     ▼
                                ┌────────────┐         ┌──────────┐
                                │  反馈      │ ◄─ 结果 │  计量器  │
                                │ φ: 学习    │         │ μ: 用量  │
                                └────────────┘         └──────────┘
```

### 4.1 三个缝要求（宿主无关性）

宿主能实现该模式当且仅当暴露：

1. **可插拔模型注册表**——能注册专家路由 `(r, id, caps)`，使下放可命名 `(r, id)` 并到达该模型。DSH 中为 `ctx.llm` + 适配器路由。
2. **子智能体委派缝**——能生成绑定到所选 `(r, id)` 的隔离子智能体，返回 `result={output, stopReason}`。DSH 中为 `ctx.subagents.start(name, {agentOptions:{provider,model}})`。
3. **流级用量事件**——下放期间能观测按所派专家归属的逐调用 token 用量。DSH 中为全局 `llm/stream` waterfall 带 `{type:'usage', usage}` chunk。

### 4.2 路由器（纯，每任务 O(1)）

路由器 `ρ` **零模型调用**——是目录与任务的纯函数。这是对异议 (2) 的解决：选专家不花往返。目录 `ranks` 是先验；除非反馈覆盖，路由器信任之。

### 4.3 下放器（并行，隔离）

`δ` 独立实现每个指派。并行是第二重经济收益：`n` 个任务并发派给 `n` 个专家，墙钟 ≈ 最大耗时，非求和。隔离是正确性收益：一个专家失败不污染另一个的上下文。两模式：

- **direct**——一次 `ctx.llm.stream`；精确 token 捕获；给纯生成任务。
- **subagent**——带自己 loop 的子智能体；给需工具的任务；用量经全局 `llm/stream` 监听器按 `sessionId == child.id` 归属。

### 4.4 反馈（闭环学习）

`φ` 持久化 `(T, E, correct, quality)`，按 (专家, 种类) 算 `successRate` 与 `avgQuality`。加成 `β`：
- ≥3 次试验且 `successRate ≥ 0.9` → +1.5（proven：加成）。
- `successRate ≤ 0.4` → −3.0（failing：降权）。

加成小于静态惩罚，故反馈*精修*先验而非冷启动——模型须先过真实质量门槛，反馈才能把它升过静态更强者。

### 4.5 计量器（成本真相）

`μ` 逐下放记录 `usage={prompt, completion, reasoning, total}`，按专家/路由/种类归属，持久化可聚合。这是问责层：无它，"路由省钱"是断言；有它，是测量。

## 5. 参考实现：`dsh-swarm-router`

实现全部四组件的 DeepSeek Harness bundle。专家目录：18 个 cfgpu 文本模型 + 3 个 OpenRouter 模型，能力标注，在 `models/registry.json`。路由器：纯、按难度匹配，在 `router.js`。下放器：`swarm_dispatch`（subagent|direct）。反馈：`swarm_feedback` + `swarm_ranking`。计量器：全局 `llm/stream` 监听器 + `swarm_stats`。

### 5.1 评估

真实 cfgpu `/chat/completions`；无 mock。基准：5 个异质任务。

| 任务 | kind | 路由专家 | 答案 | 判定 |
|---|---|---|---|---|
| 17×23 | fast | DeepSeek V4 Flash | 391 | ✅ |
| bat-ball | reasoning | GLM-5.2 | 0.05 | ✅ |
| `is_prime` | coding | DeepSeek V4 Pro | 代码 | ✅ |
| 翻译 | general | DeepSeek V3.2 | CJK | ✅ |
| widgets | reasoning | GLM-5.2 | 5 | ✅ |

4 个不同模型；27/27 内容验证 green。direct 模式逐任务精确捕获 token（如 GLM-5.2：p82+c114=196）。矩阵信号（`distinctModels=4`）确认路由确实行动而非塌缩。

### 5.2 实测成本 vs 单模型

Flash 上的平凡算术花 133 token、1.4s；同一题在 GLM-5.2 上即定理 1 的过供给情形。GLM-5.2 上的 bat-ball 陷阱答对（0.05）；在 Flash 上即欠供给情形。基准是定理两情形的具体实例。

## 6. "任何想法，皆有其专家"——表达力

该模式之力在于*专家即模型路由* `(r, id, caps)`。为新领域加专家——视觉、音频、垂直微调、自定义网关——是加路由，非重构智能体。目录开放、社区所有（一个校验过的 PR）。故：

**断言.** *任何可表达为"在某路由可达、带声明能力标签的模型"的能力，都可作为专家加入，而无需改协调器、路由器、下放器、反馈或计量器。*

这是该模式*在理论上*能实例化任何想法的意义：想法只需可归约为模型路由。已具体实现：reasoning、coding、general、fast、long-context——跨两个 provider。开放的 `K`（任务种类）与开放的 `C`（目录）意味表面靠堆积增长。

**局限.** 非 LLM 专家——确定性算法、人、物理执行器——在当前形式化之外。把 `E` 扩到含非 LLM 专家（工具即专家）是自然的未来工作：缝要求 (2) 已接纳任何返回 `{output, stopReason}` 的隔离执行器。

## 7. 讨论

- **静态排名为先验.** 目录的 1–10 排名是作者启发式。反馈回路是有原则的修正；结果累积后加成能推翻坏先验。当前阈值偏保守。
- **`reasoning_tokens` 核算.** 当服务适配器发出它时（DSH 的 `llm-deepseek`），计量器捕获之；当它把推理折进 output 时（`llm-pi-ai`，用于 cfgpu），细分缺失但 total 精确。适配器选择是核算保真度旋钮。
- **超越 DSH 的泛化.** 任何具三个缝（§4.1）的智能体 harness 都能承载该模式。这些缝最小且常见：模型注册表、子生成、流用量事件。缺 (2) 的单模型框架无法隔离专家，故无法正确实现该模式。
- **vs 混合专家（MoE）.** MoE 在*一个模型*的子网络间按 token 路由；本模式在模型*之间*按任务路由。可组合：一个专家路由本身可指向 MoE 模型。

## 8. 结论

多专家模式解耦了单模型智能体混淆的四个关注点——路由、下放、学习、核算——并证明在温和假设下按难度匹配路由帕累托优于单模型下放。DeepSeek Harness 上的首个实现在真实模型上验证了定理：五个任务、四个专家、全对、精确成本。框架的开放目录与开放种类空间使其成为堆积式基底：任何可归约为模型路由的想法，都是等待被加入的专家。
